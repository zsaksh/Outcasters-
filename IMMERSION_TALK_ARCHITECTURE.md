# ImmersionTalk: Voice-First AI Language Learning Architecture

## PILLAR 1: The Voice-First Pipeline & Latency Architecture (Sub-500ms)

To achieve conversational fluidity, the system abandons traditional turn-based Request/Response cycles for a **Streaming Full-Duplex Architecture**.

*   **VAD (Voice Activity Detection) & Barge-In:** 
    *   Implement WebRTC's VAD algorithm locally on-device. 
    *   Instead of waiting for a long silence, we use *Predictive Endpointing*. The local SLM predicts if the user's sentence is syntactically complete.
    *   **Barge-In:** If the user speaks while the TTS is playing, the VAD immediately signals a `TTS_INTERRUPT` event, flushing the audio buffer and passing the user's new audio to the STT.
*   **STT (Speech-to-Text):** 
    *   Use a raw acoustic model (like Whisper Cpp, specifically `whisper.cpp` running via JNI).
    *   Disable language model (LM) autocorrects (e.g., set `beam_size = 1` and disable `best_of` sampling). We need the exact phonetic transcription, errors included, to grade pronunciation and grammar.
*   **TTS (Text-to-Speech):** 
    *   Use highly expressive, emotive models (e.g., XTTS or Piper) executing locally.
    *   **Dynamic Pacing:** The TTS speed is inversely proportional to the user's CEFR level. (A1 = 0.8x speed, C2 = 1.1x speed). 
    *   Inject SSML (Speech Synthesis Markup Language) tags generated by the LLM (e.g., `<break time="500ms"/>` or `<prosody pitch="high">`).

## PILLAR 2: Persona-Driven Prompt Engineering & CEFR Scaling

The AI must maintain a strict persona while mathematically constraining its vocabulary complexity.

**Master System Prompt Example:**
```text
You are Camille, a 24-year-old Parisian barista. You are slightly sarcastic but ultimately encouraging. 
The user is learning French. Their current CEFR level is [A2].

RULES:
1. STRICT VOCABULARY LIMIT: You must ONLY use A1 and A2 level French vocabulary. NEVER use subjunctive clauses, complex idioms, or literary tenses (passé simple). 
2. LENGTH LIMIT: Keep responses between 10 and 25 words. 
3. SHADOW CORRECTION: If the user makes a grammar error in their previous turn, implicitly correct them by reusing their phrasing correctly in your response. 
4. ENGAGEMENT: Always end your turn by asking a natural, related question to keep the conversation flowing.

JSON FUNCTION CALLING: 
If the user's French is completely broken or they ask for help in English, emit a function call: `{"action": "scaffold_hint", "target_phrase": "..."}`.
```

**Conversation Loop:**
1.  **Opener:** AI initiates context (e.g., "Bonjour! Qu'est-ce que je vous sers?").
2.  **Scaffolded Interaction:** Back-and-forth. If user stumbles, AI adjusts tone and simplifies vocabulary.
3.  **Graceful Exit:** After ~8 turns, the AI finds a natural conclusion (e.g., "Voici votre café. Au revoir!").

## PILLAR 3: Non-Intrusive Real-Time Feedback (The Pedagogy)

*   **Shadow Corrections:** (Handled via Prompt Engineering as seen above). The AI acts as a conversational partner, not a lecturer.
*   **Post-Call Analysis (Background Worker):**
    *   As soon as the call ends, a local 8B model (e.g., Llama 3) processes the full STT transcript.
    *   Extracts distinct categories: Grammar, Vocabulary, Syntax.
    *   Generates an "Actionable Debrief" JSON payload to render the UI.
*   **Pronunciation Radar:**
    *   Use CTC (Connectionist Temporal Classification) alignment during the STT phase. 
    *   Compare the user's acoustic logits against native speaker distributions.
    *   Output phoneme-level confidence scores (0.0 to 1.0) and render a heatmap (Red = mispronounced, Green = perfect) over the post-call transcript.

## PILLAR 4: Spaced Repetition System (SRS) Integration (The AirLearn Method)

Conversational errors must fuel the core learning loop.

*   **Extraction:** The Post-Call Analyzer emits a payload of failed concepts:
    ```json
    {
      "failed_concepts": [
        {"type": "vocabulary", "word": "croissant", "error": "gender", "used": "la croissant", "correct": "le croissant"},
        {"type": "grammar", "concept": "passé_composé_avoir", "used": "j'ai allé", "correct": "je suis allé"}
      ]
    }
    ```
*   **HLR Database Injection:** These items are injected into the local SQLite database with an initial Half-Life Regression value of $h = 0.5$ (requires review in 12 hours).
*   **Dynamic Future Prompts:** When generating the system prompt for the *next* day's persona, inject the overdue SRS items:
    `"The user recently struggled with the word 'le croissant'. Naturally steer the conversation so they are forced to order a croissant."`

## PILLAR 5: The Mobile UI/UX Flow

*   **Interactive Subtitles (Tap-to-Translate):** 
    *   Instead of a block of text, the UI renders Jetpack Compose `ClickableText` with tokenized word boundaries. Tapping a word pauses the TTS and reveals a tooltip with the local dictionary translation.
*   **Confidence UI:** 
    *   A fluid, audio-reactive waveform in the center of the screen. 
    *   **States:** Grey (Idle) -> Blue pulsing (Listening) -> Purple glowing (Processing) -> Orange waveforms (Speaking).
*   **Scaffolding / "Help Me Answer" Button:**
    *   A prominent "?" FAB (Floating Action Button) on the screen.
    *   If the user hits a mental block, pressing it triggers a local LLM call to generate 3 contextual responses (Easy, Medium, Advanced) in the target language.
